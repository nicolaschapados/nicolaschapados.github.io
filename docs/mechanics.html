chapados.ca: how the pieces fit

The site builds and passes its tests, but nothing is live: the repo is private, Pages is off and DNS still points at parking pages. This page explains where each piece lives, how data flows from the CV to the site, and what remains manual.

2 · From the CV to the site: the data pipeline

The CV repository stays the single source of truth for publications. Its generator emits a machine-readable manifest; the site's sync consumes only that manifest and the PDFs, never the LaTeX, so the phone number and address in the tex can never leak.

Hand-maintained data the sync does not touch: src/data/talks.json (24 invited talks), src/data/patents.json (7 entries), src/data/selected.json (8 selected publications with notes in both languages), and scripts/publications.exclude.json.

Two themes, one design

A script in the head reads localStorage.theme, else the system preference, and stamps data-theme on the root before first paint. The toggle flips it and remembers. Tokens:

dark:  bg #101418  fg #e7e2d8  accent #d3b26a  line #2a3037
light: bg #f4f1ea  fg #14181c  accent #8f6b25  line #d8d2c6
type:  Newsreader (display) · IBM Plex Sans (text) · Plex Mono (code)
portrait: 15 px radius · shadow 0 14px 34px, centred, cast downward · brass hairline frame offset 12 px down

Bilingual routing

Every page under [lang]/ is generated twice by getStaticPaths. The language pill links to the twin page; for a post without a translation it links to the other locale's blog index. Blog lists show one entry per translationKey, preferring the reader's language and marking the other.

Markdown

Astro 7 defaults to the Sätteri processor; the config uses the unified one so remark-math + rehype-katex render math at build time, with Shiki for code in both themes.
